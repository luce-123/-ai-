    Coding Plan

    更新时间：2026-06-03

    千帆 Coding Plan 是百度千帆为开发者打造的 AI 编码订阅服务，支持接入多种主流代码模型，兼容主流 AI 编程工具，覆盖代码编写、理解与优化等场景，全面提升开发效率与代码质量。

    套餐详情

    套餐价格与限额

    套餐类型 价格 用量限制
    Coding Plan Lite ¥ 40 / 月 每 5 小时：最多约 1,200 次请求
    每周：最多约 9,000 次请求
    每订阅月：最多约 18,000 次请求
    Coding Plan Pro ¥ 200 / 月 每 5 小时：最多约 6,000 次请求
    每周：最多约 45,000 次请求
    每订阅月：最多约 90,000 次请求

    套餐额度刷新规则

    套餐额度在时间周期内耗尽后，需要等待下一个周期自动恢复额度，不会消耗其他资源包或账户余额。

    • 每5小时限额：根据实际请求发生时间，滑动5小时窗口动态刷新。
    • 每周限额：每周一 00:00:00（UTC+8）重置。
    • 每月限额：在下一个月订阅日的 00:00:00 (UTC+8) 重置。

    套餐额度使用限制说明

    • 套餐额度仅可在编程工具（如 Claude Code、Qwen Code 等）中使用，禁止以 API 调用的形式用于自动化脚本、自定义应用程序后端或任何非交互式批量调用场景。将套餐 API Key 用于允许范围之外的调用将被视为违规或滥用，可能会导致调用限流、订阅停用或账号封禁。
    • Coding Plan速率限制（并发）与套餐等级相关，平台会根据资源情况动态调整。Lite版本建议使用的终端数量不超过1个，Pro版本建议使用的终端不超过2个，多终端使用可能会导致请求失败。
    • 高峰期使用Coding Plan可能会出现请求超限情况，建议您间隔一段时间后重试或者更换其他模型。

    特别说明：如在多个实例上同时开启 OpenClaw（例如在多台机器或多个容器中运行），可能会触发平台限流策略，从而出现限流报错。

    Coding Plan与常规服务的不同点

    model 入参

    千帆Coding Plan支持以下两种方式配置模型：

    在配置文件中指定 Model Name，可实时切换模型。当前支持配置的 Model Name：

    kimi-k2.5 deepseek-v3.2 glm-5 minimax-m2.5 ernie-4.5-turbo-20260402 deepseek-v4-flash glm-5.1
    1. 在配置文件中指定模型为 qianfan-code-latest

    2.通过百度千帆控制台系统配置-订阅管理页面调整配置，调整后预计一分钟左右生效。

    BaseUrl

    Coding Plan 有专属服务接口，与常规 MaaS 服务接口不同。接口 Base URL 如下

    • 兼容 OpenAI 接口协议的Base URL：https://qianfan.baidubce.com/v2/coding，如果是接口调用，完整路径为：https://qianfan.baidubce.com/v2/coding/chat/completions
    • 兼容 Anthropic 接口协议的Base URL：https://qianfan.baidubce.com/anthropic/coding，如果是接口调用，完整路径为：https://qianfan.baidubce.com/anthropic/coding/v1/messages

    API Key

    Coding Plan 会生成专属 API Key，这个 API Key 只可以用于 Coding Plan 专属接口，接口地址参考 BaseUrl 描述

    订阅管理

    套餐退订

    Coding Plan不支持退订，购买前请谨慎选择。

    自动续费

    成功购买千帆Coding Plan后，可在控制台开通到期自动续费，避免套餐过期而导致资源释放。自动续费周期为每月，在套餐到期前的7/3/1天分别扣费，直至扣费成功。您可随时在控制台取消自动续费。

    套餐升降级

    • 支持将 Lite 套餐升级至 Pro 套餐，升级费用按剩余天数折算差价。升级后，当月剩余时间的可用额度将在原有剩余额度的基础上按比例增加。
    • 不支持从 Pro 套餐降级至 Lite 套餐。如需使用 Lite 套餐，需等待当前 Pro 套餐到期后重新购买 Lite 套餐。

    Q&A

    1.常见报错问题解答

    问题一：400 Invalid content type.image_url is only suppoby certain models

    答： 您好，使用 Coding Plan 报错 400 Invalid content type.image_url is only supported by certain models，通常是由于您使用 Coding Plan 的过程中尝试让模型识别解析上下文中的图片、视频等多模态内容，但目前 Coding Plan 中模型暂未支持图像理解能力导致。

    关于 Coding Plan 中模型支持多模态信息的功能我们正高优开发中，后续会支持，您可以关注官方文档更新情况：Coding Plan文档

    问题二：400 Message format error, index[5] should be [tool] but is [assistant]

    答： 您好，使用 Coding Plan 报错 400 Message format error, index[5] should be [tool] but is [assistant]，说明 messages 数组中的 role block 顺序不符合接口协议导致。

    通常有以下原因：

    • 三方工具拼接错误： 如果您使用的第三方工具接入 Coding Plan 后产生的报错，一般是由于第三方工具内部逻辑错误导致上下文拼接错误，您可以自行查看三方工具日志或者网络抓包分析错误原因；
    • Session 未清空： 或者您也可以排查下，是否是由于您先使用的第三方模型，然后在未清空 session 的情况下切换至 Coding Plan 继续调用，该类情况需要您清空当前会话内容，或重启第三方工具后再重试。

    您可以参考 API 接口文档中关于 messages 的 role block 协议顺序要求对比下您的输入情况：文本生成接口文档。如果是 function call 执行 tool 相关的报错，您可以参考：Function calling 接口文档 中的 role block 顺序。

    问题三：401 Coding Plan API key is not allowed for non-Coding Plan requests

    答： 您好，如果在出现该报错，通常是您的 Base Url 填写错误导致。请检查工具配置中的 Base Url 是否正确：

    • 兼容 OpenAI 接口协议：https://qianfan.baidubce.com/v2/coding
    • 兼容 Anthropic 接口协议：https://qianfan.baidubce.com/anthropic/coding

    更多配置信息及第三方工具支持方案，请参考官方文档：配置方案说明

    问题四：401 The model does not exist or you do not have access to it

    答：该问题一般是由于您使用 Coding Plan 时配置的 模型 ID 错误导致。

    解决方案：请在工具的模型配置部分，核对模型名称与文档中的 model 参数接入点 ID 是否一致。修改一致后，重启工具重试即可。

    参考文档：模型列表

    问题五：429 API rate limit reached / The current model is experiencing high demand

    答： 该报错（包含 coding_plan_cluster_rate_limited 等）通常是由于当前接口调用触发了平台限流保护策略。近期由于订阅用户量激增，部分高峰时段可能会出现请求排队或限流。

    建议优化方案：

    • 避开高峰时段：错峰使用通常可获得更稳定的体验；
    • 切换模型：根据需要切换至其他可用模型或 auto 模式，Coding Plan 支持多种主流模型灵活切换；
    • 降低频率：适当降低短时间内的调用频率，以避免触发系统限流机制。

    详情请参见官方公告：服务策略调整公告

    3. 回答异常问题解答

    问题：Coding Plan模型回答：“作为一个人工智能语言模型，我还没学习如何回答这个问题，您可以向我问一些其它的问题，我会尽力帮您解决的。”

    答：您好，当您使用 Coding Plan 时如果模型出现上述回答，一般是由于您的输入或模型输出中包含了涉敏内容，触发了大模型的安全算子并进行拦截，兜底返回了该内容。

    您可以尝试通过以下方式检查和恢复：

    （1）清空当前会话上下文内容： 根据您使用的第三方工具不同，清空会话内容的方式也不同。例如：

    • OpenClaw 需要在其控制台页面输入框中输入 /reset

    • Claude Code CLI 需要在输入框输入 /clear

    （2）排查本地文件中的敏感词汇：如果清空上下文后依然存在该问题，您可以查看第三方工具的各种 md 文件（如 OpenClaw 的 SOUL.md、USER.md）或记忆文件中是否包含有敏感词汇或内容，若有请删除后重启工具再使用。
